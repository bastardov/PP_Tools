# Правила оформления окон (WPF)

Все диалоговые окна плагина собираются на WPF по единой теме. WinForms в новых
и переделываемых окнах не используется.

Перед созданием окна прочитать этот файл целиком: половина правил появилась
после реальных падений Revit, а не из соображений вкуса.

---

## 1. Сначала проверить готовые компоненты

Три четверти окон плагина — это одна из двух форм. Не писать новое окно, пока
не убедился, что не подходит готовое.

| Компонент | Когда брать |
|---|---|
| `lib/pp_paint_dialog.py` | Набор категорий флажками, необязательное число, дополнительные галочки инструмента, выбор значения из списка с поиском, галочка «Сбросить», кнопка действия. Длинный список категорий сам получает прокрутку и кнопки «Отметить все / Снять все». Ключ `choice.picker` добавляет рядом с полем кнопку «Выбрать…» (см. `pp_param_picker`). На нём собраны четыре окрашивания панели «Теплопотери», «Коллизии» и «Окрасить рандомно». |
| `lib/pp_param_picker.py` | Окно выбора имени параметра: список с поиском, пояснение в каждой строке, двойной щелчок, Enter/Esc. Ставится РЯДОМ с полем ручного ввода, а не вместо него: встроенные и семейные параметры руками вводить всё равно надо. Вызов `ask(options, current=..., title=..., subtitle=..., owner=..., empty_text=...)`, элемент списка — строка либо `{name, display}`. Про Revit не знает: список готовит инструмент. На нём «Передача параметров по MEP-соединениям» и «Окрасить рандомно». |
| `lib/pp_params_dialog.py` | Два-три числовых поля с единицами, диапазонами, подсказками и необязательными чипсами частых значений (`presets`), плюс поясняющая схема. На нём собраны оба «3D вида» и «Соединить углом». |
| `lib/pp_check_windows.py` | Инструмент-проверка целиком: окно со списком проверок и настройками выбранной плюс немодальный отчёт с выделением и подкраской через `ExternalEvent`. Типы опций: текст, многострочный текст, «да/нет» галочкой, набор категорий, **имя параметра** (`option_type=u"param"` — поле плюс кнопка «Выбрать…»). Блок «Область проверки» включается ключом `scope`. Список параметров даёт ключ `param_provider`: `provider(option_key, values) -> options`, вызывается при нажатии кнопки и видит текущие значения всех опций; без него опция `param` остаётся обычным текстовым полем. Свой тип опции подключается ключом `option_builders`: словарь `option_type -> builder(value, option) -> (элемент, функция чтения)`. На нём собраны «Проверка Модели» и «Проверка спецификации». |
| `lib/pp_param_source.py` | Единственное место, где список параметров собирается из модели: `project_options(doc, category_ids=None, instance_only=False)` обходит `doc.ParameterBindings` и отдаёт готовые строки для `pp_param_picker` с пометкой привязки (экземпляр / тип) и числом категорий. `instance_only=True` — для инструментов, читающих значение через `LookupParameter` у экземпляра. `category_ids` включает подсчёт покрытия и поднимает полные наверх. |
| `lib/pp_mep_filter_control.py` | Конструктор условий фильтра элементов: включение, режим внутри группы и между группами, применение к источникам и приёмникам, строки «параметр — оператор — значение — группа». Формат значения — как у `pp_mep_filter.normalize_filter_config`. |
| `lib/pp_check_list.py` | Список с поиском и галочками: строка фильтра, кнопки «Все / Снять все», место под свою кнопку, счётчик отмеченного. Галочки живут отдельно от строк, поэтому фильтрация их не сбрасывает. Подсказку в строке поиска задавать ключом `search_hint` («Поиск по номеру системы — например В1»), умолчание — «Поиск по списку — начните вводить». На нём собраны списки в «Связях в шаблоне» и «Имени листа по видам». |
| `pp_wpf.show_report(...)` | Любой итоговый отчёт или сообщение об ошибке вместо `forms.alert`. Для отчётов-таблиц, где важно выравнивание колонок, — `monospace=True` и при необходимости `width`. |
| `pp_settings.show_report(...)` | Итог инструмента с учётом настроек показа отчётов. Сигнатура прежняя, первым аргументом можно передавать `None`: окно рисует `pp_wpf`. Этим отчётом пользуются полтора десятка кнопок — правка здесь меняет их все сразу. |

Оба диалога настраиваются словарём и ничего не знают про Revit — примеры вызова
в шапке каждого модуля.

Если готовое не подходит, но окно похоже на уже существующее в другой кнопке —
выносить общий компонент в `lib`, а не копировать разметку. Четыре копии одного
диалога окраски стоили ~400 строк дубля.

## 2. База: `lib/pp_wpf.py` и `lib/pp_theme.xaml`

`pp_theme.xaml` — единственное место в плагине, где допустимы хекс-цвета.
Исключение: поясняющие схемы внутри окон инструментов (см. раздел 5), но и они
берут значения только из палитры ниже.

`pp_wpf.py` даёт:

| Что | Зачем |
|---|---|
| `Notifier` | Базовый класс ViewModel, реализует `INotifyPropertyChanged` через `add_PropertyChanged` / `remove_PropertyChanged` / `notify(*names)`. Не дублировать в каждом файле. |
| `load_window_file(path)` | Разбор `.xaml` в объект `Window`, тема подключается сама. |
| `load_theme()` | Подключение темы и конвертеров в `Application.Current.Resources`. Повторный вызов безвреден. |
| `set_owner(window)` | Привязка к главному окну Revit. Без неё окно проваливается за Revit. |
| `fit_to_screen(window)` | Ужимает окно до рабочей области экрана, если размер из XAML в неё не помещается (маленький экран, масштаб Windows 125–150 %). Вызывать сразу после `set_owner`. |
| `wire_keys(window, on_accept, on_cancel)` | Enter — основное действие, Esc — закрытие. |
| `guard(status_setter)` | Декоратор обработчика: исключение уходит в строку статуса, а не роняет Revit. |
| `show_report(body, title, subtitle, is_error)` | Модальное окно отчёта в стиле плагина. |
| Конвертеры `BoolVis`, `NullVis` | Доступны в разметке как `{StaticResource BoolVis}`. |

## 3. Дизайн-система

Направление: инженерный инструмент, не офисное приложение. Плотная сетка,
светлый фон, один насыщенный акцент, минимум декора.

### Палитра (ключи из `pp_theme.xaml`)

```
Accent        #0E6E8C   основное действие, активные состояния, галочки
AccentHover   #0B5C76   наведение и нажатие на акцентных элементах
AccentSoft    #E6F1F5   подложка под наведение, выделенная строка списка
Hot           #B3541E   предупреждения, удаление, отклонения от нормы
Ink           #16232B   основной текст
Muted         #6B7C85   подписи, служебные идентификаторы, плейсхолдеры
Line          #D5DDE1   границы полей, рамки, разделители
Surface       #FFFFFF   карточки, поля ввода, фон списков
Canvas        #F4F7F8   фон окна
LogoBackdrop  #555555   подложка под logo.png в окне «Инфо»
```

Второй цвет (`Hot`) применяется точечно — обычно это строка статуса в состоянии
ошибки и счётчик проблем в отчёте. Не более одного-двух элементов на окно.

### Типографика

Шрифт — Segoe UI. Сторонний шрифт требует деплоя `.ttf` и pack URI; без явной
просьбы не подключать.

| Роль | Стиль в теме | Размер | Начертание |
|---|---|---|---|
| Заголовок окна | `H1` | 24 | Light |
| Описание под заголовком | `Subtitle` | 13 | Normal, Muted |
| Основной текст, строки списка | `Body` | 13 | Normal |
| Подпись над блоком | `FieldLabel` | 11 | SemiBold, Muted, ЗАГЛАВНЫМИ |
| Подпись под элементом, единицы | `Caption` | 10.5 | Normal, Muted |
| Строка статуса | `Status` | 12 | Normal, Muted |
| Пустое состояние списка | `EmptyState` | 13 | по центру, Muted |

### Метрика

```
Поля окна            20
Между блоками        14
Внутри блока          6
Padding кнопки       22,8   (основная 24,8)
Padding поля ввода   10,7
Радиус скругления     4      (чипсы — половина высоты, чекбокс — 3)
Толщина рамки         1      (чекбокс 1.5, обводка иконки 1.8)
Кнопка панели        34×34, иконка 20×20
```

### Готовые стили

`Button.Primary`, `Button.Flat`, `Button.Tool`, `TextBox.Field`, `PP.CheckBox`
(трёхпозиционный), `RadioButton.Chip`, `ToggleButton.Expander`, `PP.ListBoxItem`,
`PP.NavItem` (пункт бокового меню), `PP.TreeViewItem`, `Card`, `Card.Result`
(блок итога: подложка `AccentSoft` + полоса `Accent` слева), `Body.Result`
(текст итога, 15 SemiBold), `Rule`, `EmptyState`, `PP.ScrollBar`, `PP.ToolTip`.

У `TextBox.Field` есть подсказка внутри поля: текст кладётся в `Tag`
(`<TextBox Style="{StaticResource TextBox.Field}" Tag="Поиск по имени"/>` или
`box.Tag = u"…"` из кода). Серый текст виден, пока поле пустое, щелчку по полю
не мешает.

### Интуитивность: правило «бери и делай»

Главное правило интерфейса плагина: пользователь смотрит на окно и сразу
понимает, что делать. Никаких «а это что за поле?» — если такой вопрос возник,
это дефект окна, а не невнимательность пользователя.

- **Ни одного безымянного поля.** У каждого поля ввода либо подпись
  (`FieldLabel`) сверху, либо видимая подсказка внутри (`Tag` у
  `TextBox.Field`). **`ToolTip` подписью не считается**: его не видно, пока не
  наведёшь мышь. Пустая рамка без подписи — самая частая ошибка, на ней уже
  спотыкались (строка поиска в `pp_check_list`).
- **Подсказка называет действие и даёт пример**, а не тип данных: «Поиск по
  номеру системы — например В1», а не «Введите текст».
- **У списка рядом с полем есть объяснение, что даст щелчок:** «Готовые
  варианты из настроек — щёлкните по строке, и она подставится в поле выше».
  Список без такой строки читается как непонятный довесок.
- **Видно, что выбрано.** Если щелчок по строке меняет поле — выбранная строка
  остаётся подсвеченной; правка поля руками подсветку снимает. Состояние списка
  и поля не расходятся.
- **Результат виден до нажатия кнопки и выделен.** Блок предпросмотра («ИМЯ
  ЛИСТА БУДЕТ ТАКИМ») оформляется стилями `Card.Result` + `Body.Result`:
  подложка `AccentSoft`, полоса `Accent` слева, текст 15 SemiBold. Глаз должен
  цеплять итог сразу, не разыскивая его среди одинаковых белых карточек. Такой
  блок в окне ровно один — иначе выделение перестаёт работать. Пока ввод
  неполный, в блоке приглушённым (`Muted`) текстом написано, что сделать.
- **Правка в полях редактора не пропадает.** Если поля справа заполняются ИЗ
  выделенной строки списка, пользователь читает их как свойства этой строки, а
  «Сохранить» — как «записать всё, что я вижу». Поэтому:
  заголовок блока итога называет действие («ВЫДЕЛЕННАЯ СТРОКА СТАНЕТ ТАКОЙ» /
  «БУДЕТ ДОБАВЛЕНА СТРОКА»), а не висит статичной подписью; основной кнопкой
  (`Button.Primary`) становится нужная сейчас — при выделенной строке
  «Изменить строку», иначе «Добавить строку»; Enter внутри полей записывает
  строку, а не закрывает окно; «Сохранить» с несохранённой правкой применяет её
  сам, а если применить нельзя — окно НЕ закрывается и пишет причину в статус.
  На этом уже споткнулись в «Шаблоне марок»: правка поля «до» молча терялась,
  окно при этом отчитывалось «сохранено».
- **Умолчания рабочие.** Окно открывается в состоянии, из которого можно сразу
  нажать основную кнопку и получить осмысленный результат.
- **Порядок блоков сверху вниз = порядок действий.** Что делать первым — выше.
- **Удобный размер из коробки.** Окно открывается таким, чтобы работать сразу,
  без растягивания мышью: главный список виден на 6–8 строк, предпросмотр и
  кнопки помещаются без прокрутки. Огромным делать не надо — ориентир для окна
  со списками `Height="780…860"`, `MinHeight` на 150–200 меньше. Главной
  области (`Height="*"`) задавать `MinHeight` (~260), иначе при сжатии она
  схлопывается до двух строк, а фиксированные блоки съедают всё. Обязательно
  `pp_wpf.fit_to_screen(window)` после `set_owner` — на экране 1366×768 или при
  масштабе 150 % окно ужмётся, а не уедет за край.
  Проверка: посчитать, сколько строк списка видно при `Height` по умолчанию.
  Три — мало, окно будут растягивать каждый раз.
- Проверка перед сдачей: посмотреть на окно как на скриншот, не читая заголовок
  и описание. Если хоть один элемент требует объяснения — переделать, а не
  дописывать пояснение в описание сверху.

### Поведение

- Наведение меняет фон или границу, но не сдвигает элемент.
- Активный чипс — заливка `Accent`, белый текст.
- Дизейбл — прозрачность 0.45, курсор Arrow.
- Пустой список — не пустая рамка, а строка по центру: что случилось и что
  делать. «Список пуст. Введите значение ниже и нажмите „Добавить“.»
- Ошибка пишется в строку статуса цветом `Hot`, не в `MessageBox` и не в
  `forms.alert`.
- Кнопка называется глаголом действия, и тот же глагол уходит в статус:
  «Найти пересечения» → «Найдено 14 пересечений».
- Кнопка действия блокируется, пока ввод некорректен, а статус объясняет почему.
  Не показывать окно с ошибкой после нажатия.
- Подтверждение удаления не нужно, если изменения уходят на диск только по
  кнопке «Сохранить»: статус пишет «Удалено „X“. Отмена вернёт всё как было».
- Длинные пояснения прятать под `ToggleButton.Expander` с надписью «Подробнее»,
  а не выкладывать стеной текста.

## 4. Схема окна и файлов

```
<Кнопка>.pushbutton/
    script.py               тонкий: настройки, sys.path, вызов окна, логика Revit
    ui.xaml                 разметка (или setup.xaml + report.xaml, если окон два)
    pp_<имя>_window.py      ViewModel и класс окна
```

`script.py` добавляет свою папку в `sys.path`:

```python
_HERE = os.path.dirname(os.path.abspath(__file__))

if _HERE not in sys.path:
    sys.path.append(_HERE)
```

Модули из `lib` (`pp_wpf`, `pp_paint_dialog`, `pp_params_dialog`) импортируются
без этого — pyRevit кладёт `lib` в путь сам.

### Скелет разметки

```
Заголовок (H1)
Описание одной строкой (Subtitle), если окно не самоочевидно
Блок фильтров / параметров
Основная область: список, дерево или таблица, растягивается по высоте
Разделитель (Rule)
Строка статуса слева  |  Отмена + Основное действие справа
```

### Разделение обязанностей

- `SomeWindowVM(pp_wpf.Notifier)` — всё состояние и вся проверка ввода.
- `SomeWindow(object)` — загрузка XAML, построение динамических контролов,
  подписки. Обработчик вызывает метод VM и больше ничего не делает.
- Логику расчётов не трогать: окно — оболочка над готовой функцией. Если у
  инструмента была функция `ask_options()`, сохранить её имя и формат возврата,
  чтобы весь код ниже остался нетронутым.

### Модальность

- `ShowDialog()` — окно собирает параметры и закрывается.
- `Show()` + `ExternalEvent` — окно должно работать с моделью, не закрываясь.
  Обращение к `doc` из немодального окна только через `ExternalEvent`, прямой
  вызов из обработчика даст исключение Revit API.
- Ссылку на немодальное окно держать в списке уровня модуля, иначе его соберёт
  сборщик мусора.

## 5. Грабли IronPython и WPF

Проверить каждый пункт перед сдачей окна. Пункты 1–4 — реальные падения.

1. **`Setter TargetName` умеет целиться только во `FrameworkElement`.**
   `<Setter TargetName="ArrowRotate" Property="Angle">`, где `ArrowRotate` —
   это `RotateTransform`, роняет `XamlReader.Load` с `KeyNotFoundException`
   внутри `DependencyPropertyConverter`. Поворот задавать через
   `RenderTransform` самого элемента.
2. **Структуры в `ResourceDictionary` разбираются ненадёжно.** `<sys:Double>`,
   `<CornerRadius>`, `<Thickness>`, `<FontFamily>` как ресурсы — убраны из темы.
   Метрику писать прямо в стилях.
3. **Неявные стили красят сам Revit.** `<Style TargetType="ScrollBar">` без
   `x:Key` в `Application.Current.Resources` перекрасит полосы прокрутки всего
   Revit. Держать keyed (`PP.ScrollBar`, `PP.ToolTip`) и подключать в каждом
   окне:

```xml
<Window.Resources>
  <Style TargetType="ScrollBar" BasedOn="{StaticResource PP.ScrollBar}"/>
  <Style TargetType="ToolTip" BasedOn="{StaticResource PP.ToolTip}"/>
</Window.Resources>
```

4. **`GridLength(1, 1)` — это пиксели, а не звёздочка.** В `GridUnitType`
   `Auto=0, Pixel=1, Star=2`. Писать `GridLength(1, GridUnitType.Star)`.
5. **Конвертеры не резолвятся из XAML-строки.** `XamlReader` не видит
   python-типы. Экземпляр кладётся в `Application.Current.Resources` до загрузки
   XAML — этим занимается `pp_wpf.load_theme()`.
6. **Обработчики по имени из XAML не подхватываются.** Атрибут `Click="OnRun"`
   не сработает. Только `x:Name` + `window.FindName('BtnRun').Click += handler`.
7. **Замыкания в цикле.** `for i in range(5): btn.Click += lambda s, e: f(i)`
   отдаст всем кнопкам последнее `i`. Использовать фабрику обработчиков.
8. **`ObservableCollection` объявляется как `ObservableCollection[object]()`.**
   Для больших списков хранить строки, а объекты — параллельным python-списком
   по индексу: так тысячи строк не строятся поэлементно.
9. **Фильтрация больших списков.** `ICollectionView.Filter` с python-предикатом
   вызывается из .NET на каждый элемент и тормозит уже на тысяче строк.
   Пересобирать `ObservableCollection` в Python.
10. **Асинхронности нет.** Долгая операция вешает UI. Для длинных прогонов
    использовать `forms.ProgressBar` из pyRevit (это не диалог, его оставляем)
    или обновлять `ProgressBar` из `ExternalEvent`, разбив работу на порции.
11. **Таймеры — только `DispatcherTimer`**, не `WinForms.Timer` и не `Idling`.
12. **Исключение в обработчике роняет Revit молча.** Оборачивать через
    `pp_wpf.guard(...)`.
13. **Плоский скрипт без общего `try`.** Если `script.py` не обёрнут в
    `try/except`, функция `fail()` не должна бросать исключение — она показывает
    окно и выходит через `sys.exit(0)`. Бросать `Stop` можно только там, где
    есть ветка `except Stop`.
14. **`XamlParseException` сообщает только номер строки.** `pp_wpf` печатает
    файл, строку и соседей — читать это, а не разбирать стек на сотню строк.
15. **Шапка таблицы вне списка разъезжается со строками.** Если заголовки
    колонок лежат отдельным `Grid` над `ListBox`, их отступы должны повторять
    весь путь до содержимого строки: рамка карточки + `Padding` списка +
    `Padding` строки. Плюс справа зарезервировать ширину полосы прокрутки и
    выставить `ScrollViewer.VerticalScrollBarVisibility="Visible"`, иначе при
    её появлении строки сузятся и уедут относительно шапки. Для темы плагина
    это `13,0,25,6` — 1 + 4 + 8 слева, те же 13 плюс 12 справа. Задаётся
    `Margin` у самого `Grid` шапки либо `Padding` у обёртки `Border`, если
    колонки строятся кодом. Отдельных отступов у заголовков колонок быть не
    должно: они собьют выравнивание.
    Ошибка повторялась дважды — сначала в «Статистике», потом в отчёте
    проверок. Правило есть в валидаторе, проверять им ВСЕ окна, а не
    только то, где заметили.
16. **Ряд кнопок в колонке фиксированной ширины обрезается.** `StackPanel` с
    `Orientation="Horizontal"` не переносит содержимое: если сумма ширин
    больше колонки, последняя кнопка молча обрежется. В колонке фиксированной
    ширины использовать `WrapPanel` и сжимать `Padding` кнопок до `14,8`
    (базовые `22,8` рассчитаны на подвал, а не на ряд из трёх).
    В подвале колонка обычно `Auto` и обрезки нет — но там ряд должен
    помещаться в `MinWidth` окна, иначе обрежется само окно.
17. **Кэш sandbox.** После правки файла в расширении оболочка может видеть его
    обрезанным. Проверять синтаксис на копии в рабочей папке.
18. **Выделение в списке ставить ПОСЛЕ подписок.** `lst.SelectedIndex = 0`
    внутри заполнения контролов, когда обработчики ещё не привязаны, уходит в
    пустоту: строка подсвечена, а всё, что должно было подгрузиться по
    `SelectionChanged`, не подгрузилось. В «Шаблоне марок» из-за этого дерево
    семейств было пустым до первого щелчка по категории. Начальный выбор — в
    отдельном шаге после `_wire()`, и если индекс уже такой, звать обработчик
    руками.
19. **Выбор элемента мышью при открытом модальном окне.** `PickObject` из
    обработчика модального окна (даже после `Hide()`) вешает Revit. Окно надо
    закрывать, возвращая скрипту запрос на выбор и всё своё состояние, а затем
    открывать заново — `script.py` крутит цикл. Так сделаны кнопки «С плана» в
    «Шаблоне марок».

- [ ] При размере по умолчанию главный список виден на 6–8 строк, растягивать не нужно

- [ ] Пустое состояние списка обработано текстом
- [ ] Обработчики обёрнуты в `pp_wpf.guard`, ошибка идёт в статус
- [ ] Окно закрывается по Esc, основное действие висит на Enter
- [ ] Владелец окна назначен на главное окно Revit
- [ ] Немодальное окно трогает `doc` только через `ExternalEvent`

- [ ] Формат сохраняемых настроек не изменился

### Автоматические проверки

Прогнать на копиях файлов (python3 в рабочей папке, не в расширении):

1. `ast.parse` каждого `.py` — синтаксис.
2. `xml.etree.ElementTree.fromstring` каждого `.xaml` и каждой встроенной
   XAML-строки — валидность разметки.
3. Каждый `Setter TargetName` внутри `ControlTemplate` ссылается на
   существующий `x:Name`, и целевой тег не `*Transform`, `*Brush`, `*Geometry`.
4. Каждый `{StaticResource X}` есть среди `x:Key` темы или среди конвертеров.
5. Каждый ключ, который код берёт из ресурсов по имени, есть в теме.
6. Каждый `FindName("X")` совпадает с `x:Name` в разметке, включая имена,
   собранные конкатенацией.
7. Каждый `{Binding Property}` совпадает со свойством ViewModel.
8. Каждый `ElementName=X` совпадает с `x:Name`.
9. Нет `GridLength` с числовым вторым аргументом.
10. Нет объявленных и неиспользуемых функций и висячих имён от убранных
    импортов.
11. **Нет имён, которые используются, но нигде не связаны.** Собрать все
    связывания модуля (импорты, присваивания, `def`, `class`, аргументы,
    `except ... as`) и вычесть из загружаемых имён. Это ловит главную ошибку
    массовой правки: блок замены захватил лишнее и унёс с собой нужный импорт
    или функцию. Модули с `from ... import *` проверять только на собственные
    имена — API-имена оттуда не видны.

    На этой проверке уже нашлись `from pyrevit import script`, вырезанный
    вместе с `forms`, и функция `build_unique_view_name`, попавшая внутрь
    заменяемого блока. Прогонять её ПО ВСЕМ переведённым файлам, а не только
    по текущему.
