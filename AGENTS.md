\# Project rules



Проект: pyRevit extension для Revit 2022.



\## Сопутствующие файлы

\- `ICONS.md` — правила оформления иконок (размер, фон, формат, имя файла). Перед созданием или заменой иконки обязательно открыть `ICONS.md` и следовать ему.

\- `Memory.md` — подробная память по проекту: описание панелей, инструментов и модулей `lib`, принятые решения и нюансы реализации. `AGENTS.md` содержит только общие правила; всё детальное — в `Memory.md`. Перед работой над конкретным инструментом сначала прочитать соответствующий раздел `Memory.md`, после изменений — обновить его.

\- `bundle.yaml.MD` — правила оформления `title` и `tooltip` в `bundle.yaml` для кнопок pyRevit. Перед созданием новой кнопки или изменением пользовательского описания существующей кнопки обязательно открыть `bundle.yaml.MD` и следовать ему.

\- `UI.md` — правила оформления диалоговых окон на WPF: готовые компоненты из `lib`, палитра, типографика, метрика, схема файлов окна, грабли IronPython и чеклист готовности. Перед созданием или переделкой ЛЮБОГО окна инструмента обязательно открыть `UI.md` и следовать ему.



\## Предварительный анализ структуры

Перед стартом любых работ агент обязан сначала проанализировать текущую структуру папок и файлов внутри плагина.

\- Проверить расположение табов, панелей, кнопок, `lib` и служебных файлов.

\- Учитывать, что пользователь мог вручную изменить структуру, имена папок, состав инструментов или вложенность.

\- Не делать предположений о структуре только по шаблону проекта или прошлым изменениям.

\- Перед созданием новых файлов или переносом существующих сверяться с фактической структурой в рабочем каталоге.

\- Если обнаружены ручные корректировки пользователя, не затирать их и учитывать их при дальнейших изменениях.



\## Важные ограничения

\- Python: IronPython 2.7.

\- Не использовать f-string.

\- Не использовать pathlib.

\- Не использовать Python 3 синтаксис.

\- Все строки для русского текста писать через u"...".

\- Кодировка файлов: UTF-8.

\- Не менять структуру папок без явной команды.

\- Не переписывать весь проект без необходимости.

\- После правок сохранять совместимость с pyRevit.

\- Revit API проверяется вручную через pyRevit Reload.

\- Если правится кнопка, менять только соответствующий script.py и нужные файлы из lib.



## Контроль версий (git) — вместо ручных копий

С 24.08.2026 история правок ведётся в git прямо в папке расширения.
Папка `BACKUPS` вынесена из расширения в
`AppData\Roaming\pyRevit-Master\PP_Tools_BACKUPS` и больше не пополняется.

### Правило для агента

Ручные резервные копии папок и файлов НЕ создавать. Никаких новых папок
`BACKUPS`, `*_old`, `*_backup`, `script_2.py` и подобного — их роль полностью
закрывает git.

Порядок работы над правкой:

1. Перед началом убедиться, что рабочее дерево чистое: `git status --short`.
   Если есть незакоммиченные изменения пользователя — не затирать их, сначала
   сообщить о них.
2. Внести правку в нужные файлы (по-прежнему: только тот `script.py` и те
   файлы `lib`, которых касается задача).
3. После правки — коммит одной осмысленной порцией:
   `git add -A && git commit -m "<кнопка/модуль>: что изменено и зачем"`.
4. Если правка оказалась неудачной, откат делается git-ом, а не копиями:
   `git checkout -- <файл>` для несохранённого, `git revert <хэш>` для
   закоммиченного.

### Сообщение коммита

Первая строка — до 72 символов, вида `<область>: <что сделано>`, например:

```text
Марки: кнопка 10 учитывает пересечение уровня стояком
lib/pp_wpf: общий помощник plural() вместо копий в окнах
```

Дальше, через пустую строку, — короткое пояснение «зачем», если причина
неочевидна из первой строки.

### Отчёт после правки

После коммита агент обязан сообщить:

* хэш и первую строку коммита;
* список изменённых файлов (`git show --stat --oneline HEAD`).

### Для пользователя

В корне расширения лежит `git_сохранить.bat` — показывает изменения,
спрашивает описание, делает коммит и отправляет на сервер, если настроена
удалёнка. Это замена прежнему ручному копированию папок.


\## Память по инструментам (`Memory.md`)



Чтобы рабочая память агента не захламлялась, подробное знание о проекте хранится не в `AGENTS.md`, а в отдельном файле `Memory.md`.



Разделение ответственности:



\* `AGENTS.md` — общие правила, ограничения и процессы (как работать).

\* `Memory.md` — конкретика по проекту: что делает каждая панель и инструмент, какие модули `lib` они используют, ключевые параметры и принятые решения (что внутри).



Правила работы с `Memory.md`:



\* Перед доработкой инструмента агент сначала читает его раздел в `Memory.md`, а не разбирает весь проект заново.

\* После значимых изменений (новый инструмент, изменение логики, рефакторинг, новый параметр в `lib`) агент обновляет соответствующий раздел `Memory.md`.

\* В `Memory.md` держать только устойчивое знание, полезное для понимания и анализа проекта. Не дублировать сюда исходный код целиком и не писать одноразовые детали конкретной задачи.

\* Цель — чтобы новый агент, открыв `AGENTS.md` + `Memory.md`, мог быстро подхватить плагин и работать без перечитывания всех `script.py`.

\## Учёт использования (обязательно для новых кнопок)

В плагине работает своя телеметрия: `lib/pp_usage.py` пишет каждый запуск
инструмента в `telemetry/pp_usage_YYYY-MM.jsonl`.

При создании ЛЮБОЙ новой кнопки агент обязан добавить в её `script.py` сразу
после строки кодировки:

```python
\# --- учёт использования (см. lib/pp_usage.py) ---
try: import pp_usage; pp_usage.log(__file__)
except Exception: pass
```

\- Без этой строки запуски кнопки не попадут в статистику.
\- Строка намеренно обёрнута в `try/except` — логирование не должно ломать инструмент.
\- Встроенную телеметрию pyRevit НЕ использовать и НЕ включать через API: она
  сохраняет путь экранированным и молча отключается (подробности в `Memory.md`).

Кроме кнопки и пользователя запись хранит сведения о модели: `model` (имя без
суффикса пользователя), `model_key` (путь центральной модели — общий для всех
участников), `doc_guid` и `session` (запуск Revit). Группировать записи по
модели только через `pp_usage.get_model_label()` / `get_model_id()` — они умеют
разбирать и старые записи, где было лишь поле `doc`. Напрямую по `doc` не
группировать: у локальных копий заголовки разные.

## Окна инструментов — только WPF

Диалоговые окна плагина переводятся с WinForms на WPF по единой теме. Подробные
правила — в `UI.md`, здесь только то, что нарушать нельзя.

- Новое или переделываемое окно собирается на WPF. `System.Windows.Forms`,
  `MessageBox` и `forms.alert` в таких окнах не используются.
- Общая тема — `lib/pp_theme.xaml`, единственное место с хекс-цветами. Окно
  ссылается на ключи темы, а не объявляет свои цвета.
- База окна — `lib/pp_wpf.py`: `Notifier`, `load_window_file`, `set_owner`,
  `wire_keys`, `guard`, `show_report`. Не дублировать это в кнопках.
- Перед написанием нового окна проверить готовые компоненты:
  `lib/pp_paint_dialog.py` (категории флажками + число + сброс) и
  `lib/pp_params_dialog.py` (несколько числовых полей со схемой). Похожие окна
  в разных кнопках выносить в общий компонент `lib`, а не копировать разметку.
- Логику инструмента при переделке окна не переписывать: сохранять имена и
  формат возврата функций вроде `ask_options()`, чтобы код ниже не менялся.
- Перед сдачей окна пройти чеклист из `UI.md` и прогнать перечисленные там
  автоматические проверки.

\## Заголовки панелей (title без номера) — обязательно

Папки панелей и кнопок нумеруются префиксом `NN_` только для порядка сортировки.
В ленте Revit номер показываться НЕ должен.

\- У КАЖДОЙ панели (`*.panel`) обязателен файл `bundle.yaml` с полем `title`,
  содержащим чистое имя без номера. Пример для `06_Рабочие инструменты.panel`:

```yaml
title: "Рабочие инструменты"
```

\- Без `bundle.yaml` pyRevit берёт имя из папки и показывает префикс (напр.
  «06_Рабочие инструменты»). Поэтому при создании ЛЮБОЙ новой группы/панели агент
  обязан сразу добавить её `bundle.yaml` с `title` без цифр.
\- У кнопок имя в ленте тоже задаётся `title` в их `bundle.yaml` (можно с `\n`
  для переноса), а не именем папки.
\- Изменения раскладки применяются после `pyrevit caches clear --all` и запуска
  Revit; иначе заголовок панели может «прыгать» с номером (устаревший кэш).
